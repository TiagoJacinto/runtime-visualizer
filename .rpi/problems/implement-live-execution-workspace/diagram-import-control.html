System Design decision

Does “Imports” change the snapshot or only its presentation?

An Analysis revision is the immutable source, dependency, graph, and diagnostic snapshot that a run is pinned to. The graph’s Imports control can either change that snapshot identity or simply reveal contextual import nodes already available in it.

Option A

Display-only preference

One Analysis revision; the control only hides or reveals import context in the graph.

checkout.ts › calculateTotal › 7bc114
Control-flow graph
import { tax }
subtotal = reduce()
return subtotal
1 import { tax } from "./tax"
2 export function calculateTotal() {
3 return subtotal
4 }

Toggle Imports off: the dashed import node disappears. The selected revision remains 7bc114, its history position and runnable snapshot do not change.

  • Simple revision history and badge logic.
  • The snapshot must retain import context even when initially hidden.
  • Runs never differ because of a view preference.
Option B

Distinct revision variant

The setting participates in analysis identity, so each control state selects a different snapshot.

checkout.ts › calculateTotal › 7bc114 · imports on
Control-flow graph
import { tax }
subtotal = reduce()
return subtotal
1 import { tax } from "./tax"
2 export function calculateTotal() {
3 return subtotal
4 }

Toggle Imports off: the Workspace selects 7bc114 · imports off. It appears as a different revision even though the source and dependencies are identical.

  • Matches the current analyzer’s flag-sensitive graph generation.
  • Duplicates history entries and can make a view toggle look like a code change.
  • Runs can be pinned to separate graph variants for identical source.
Recommended

Use display-only Imports

Operators perceive this as a graph visibility control, not a source change. A single immutable revision avoids duplicate history and keeps execution identity tied only to executable source and dependencies.
